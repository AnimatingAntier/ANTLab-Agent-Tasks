# 冻结前评分规则

1. HTTP/API 成功、模型 JSON 格式正确、答案正确、引用 ID 存在、引用内容支持答案分别评价。
2. 每个正式条件固定 8 题。首次失败、格式错误、无答案计入主分母；重试另列，不替换首次。
3. 数值按完整字符串解析并精确比较，允许等值小数；百分比要求百分号，不用子串命中。其他表达由有理由的复核覆盖。
4. 正确数值可能来自错误批次，答案正确不等于引用支持。引用支持需核对实际输入中的主体、版本、时间、批次和完整推导。
5. 记录逐例证据覆盖。K 遗漏必要证据时合理拒答可单独标记，但若完整资料可回答，拒答不计任务正确。
6. 资料确实未提供的问题，正确答案为“证据不足”；不能补猜硬件等信息。拒答引用仍需复核。
7. 开发题参考答案来自公开 dev_answers。评测题标签在代码、配置、规则冻结及主请求完成后独立推导，保留原句与过程。
8. 尚无标签或语义复核的结果保持未核验，不用模型自评或引用存在替代人工支持判断。助手整理的标签明确标记来源与用户未核验。
9. reviews.jsonl 以 run_id 关联，追加修订保留历史，后写条目生效。条目含 reason 和 judgment_source；不得冒写 human。
10. 未完成批次可导出临时汇总，但 provisional=true；报告不得当作正式结果。中断状态保留，审计后人工决定是否重试。
